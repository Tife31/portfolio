## Project overview
This project fetches finiacl dat from my bank  (CIBC), perocesses credit card balances, limit and other dat. Then schedules reminders for upcoming payment due dates. The goal is to ensure I never miss a payment and maintain a clear overview of my credit usage.

## How It Works

Retrieve Financial Data
The script connects to Plaid API to pull in bank account and credit card details.
It extracts key information: available balance, total credit limit, and current spending.

Calculate Credit Usage
The system determines how much credit is used vs. the total limit.
It flags high usage to encourage better financial decisions.


Schedule Payment Reminders
The script integrates with Google Calendar API to create reminders for credit card due dates.
It ensures that each account's due date is tracked and notifies the user in advance.


## Future Improvements

Enhancing security measures with encrypted storage.

## Implementing security into the Plaid API Project: 
1. Secure Authentication with OAuth 2.0
Plaid provides an OAuth authentication flow, but if using API keys, store them securely using environment variables or a secret manager.
Rotate API keys periodically and apply the principle of least privilege.
2. Data Encryption & Storage Security
Ensure sensitive financial data (like account balances and transactions) is encrypted at rest using AES-256.
Use TLS 1.2+ for securing API requests in transit.
Avoid logging sensitive user data in plaintext.
3. API Security & Rate Limiting
Implement API request validation using HMAC signatures to prevent unauthorized modifications.
Use Plaid’s IP whitelisting to restrict access from untrusted sources.
Apply rate limiting (e.g., 100 requests per minute) to prevent abuse.
4. Secure Webhooks & Callback URLs
Verify webhook signatures to ensure the data comes from Plaid.
Avoid exposing sensitive information in webhook responses.
Restrict callback URLs to prevent open redirect vulnerabilities.
5. Monitoring & Logging for Threat Detection
Log all authentication attempts and API errors for auditability.
Use SIEM solutions (e.g., Splunk, ELK) to monitor for anomalies.
Set up alerts for unauthorized access attempts or failed API calls.
6. Compliance & Privacy Considerations
Ensure GDPR/CCPA compliance by allowing users to delete their financial data upon request.
Implement data masking for non-admin users viewing transaction history.
